# 知画重构：服务边界与接入约定

更新：2026-09-16。客户端和服务端在各自 `main` 分支持续开发，初版不保留旧工作流标识或旧作品 schema 的兼容层。

## 对象边界

- `paragraphId` 表示讲解逻辑，`visualId` 表示时间线中的呈现单元，`jobId` 表示一次不可变推理。三者不能相互替代。
- 画面展示时长与模型允许的 4～15 秒生成时长分别校验。服务只负责生成素材，桌面端负责作品时间线、字幕、旁白混音和正式导出。
- 候选、采用和增强分别记录。增强针对指定候选，不能因换候选继续冒充正式增强结果。

## 图像与视频任务

- 客户端只能提交受信任 `workflow_id` 和经过校验的参数，不能上传任意 ComfyUI 图。
- `client_request_id` 是幂等键。断线或桌面重启后先恢复原任务，不能静默重复发起付费推理。
- 输入上传、SQLite 状态、进度、结果清单、鉴权下载和 Range 续传沿用同一协议。健康检查和模型可见性不等于端到端推理通过。
- 顺序、智能和自定义并发由用户选择。服务端不会自行购买实例；多 worker 需要当前地域库存与真实分发验收。

## IndexTTS 2.5 旁白任务

- `voice_clone` 仅接受 `indextts-2.5-v1`。它由独立 `IndexTtsExecutor` 执行，不加载 ComfyUI，也不污染知画服务虚拟环境。
- 参考音频必须来自本次鉴权上传目录；路径越界会被拒绝。每个任务写入隔离请求文件并启动 IndexTTS 独立 Python 子进程。
- 完成后只返回一个 `audio` artifact，仍使用标准结果清单和续传下载。取消会终止子进程，服务重启后未完成的外部进程任务明确失败，客户端可人工重试，不伪装为仍在运行。
- `/capabilities.available_workflows` 仅在 IndexTTS 代码目录、Python 和检查点均有效时包含该工作流。安装或模型可见性必须按目标地域重新验证。

Edge TTS 与 ZipVoice 在桌面端运行：Edge 是联网预设声音，ZipVoice 是按需配置的本地克隆。CosyVoice、Melo、Kokoro、Windows 系统声音和 ZipVoice 固定演示音色不属于当前默认方案。

## 发布门槛

冻结服务镜像前必须完成当前目标地域上的 Qwen 图片、H3 四类视频、SeedVR2、IndexTTS 2.5 真实任务，以及中断恢复、下载校验和至少两台 worker 的分发测试。模型/节点可见、实例创建成功和端到端结果可用分别记录，不能混为一项。
